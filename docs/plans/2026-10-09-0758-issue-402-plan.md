## Implementation Units

### U1. Share the start of a timed script or function call in the engine

**Goal:** `runShell`, `runStepShell`, `runFunction` and `runStepFunction` share one helper for the timed context, the cancel registration and the goroutine, so `dupl` finds no clone between `internal/engine/shell.go` and `internal/engine/function.go`.

**Requirements:** R4. KTD3.

**Dependencies:** none.

**Files:**
- `internal/engine/shell.go`
- `internal/engine/function.go`
- Tests that already cover these paths: `internal/engine/shell_test.go`, `internal/engine/function_test.go`, `internal/engine/step_test.go`

**Approach:**
- Add a generic helper beside `stopScript`, keyed the same way (`K comparable` over `e.shells` or `e.steps`). It makes the context with `shellTimeout` in the loop, registers its cancel under the key, and returns the goroutine. The goroutine defers the cancel and runs a call given the context.
- Each of the four methods passes its map, its key and a closure that runs the script or function and posts its own ended input.
- Keep the doc comment's invariant on the helper: the context is made in the loop, so a following stop always finds it.

**Patterns to follow:** `stopScript[K comparable]` in `internal/engine/shell.go`.

**Test scenarios:**
- Test expectation: none, because behaviour does not change. The existing tests are the proof: shell and function actions and steps end with their outcome, a stop cancels a running script or function, and a timeout ends it (`shell_test.go`, `function_test.go`, `step_test.go`).

**Verification:** `go test -race ./internal/engine` passes unchanged, and `dupl` reports nothing in `internal/engine`.
