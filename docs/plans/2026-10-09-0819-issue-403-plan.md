## Implementation Units

### U2. Share the recording of scripted reports in the fake tracker

**Goal:** `StatusBoard` and `PullRequestBoard` record their reports through one generic helper, so `dupl` finds no clone in `internal/fake/tracker.go`.

**Requirements:** R4. KTD3.

**Dependencies:** none.

**Files:**
- `internal/fake/tracker.go`
- `internal/fake/tracker_test.go`

**Approach:**
- Add a small generic type for "reports by issue key with scripted failures", next to `failures`. It holds the failures and the map, and records a value unless a failure is scripted for the key. The board keeps its mutex, wraps the failure in its own error message, and returns copies.
- Both boards hold one as a field. Their exported methods and error texts do not change, so no engine test changes.

**Patterns to follow:** `failures` with `add` and `pop` in `internal/fake/tracker.go`.

**Test scenarios:**
- A `PullRequestBoard` records two reports for one key in order, and `PullRequestReports` returns them. The package has no direct test of this board today.
- With one failure scripted by `FailPullRequests`, the first report returns an error that wraps it and names the issue, and is not recorded. The second report is recorded.
- The existing `TestStatusBoardRecordsStatusesAndScriptsTheirFailures` passes unchanged.

**Verification:** `go test -race ./internal/fake ./internal/engine` passes, and `dupl` reports nothing in `internal/fake`.
