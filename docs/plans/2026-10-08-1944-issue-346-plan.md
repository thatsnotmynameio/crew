## Product Contract

### Summary

The Claude Code adapter keeps the tokens of each model Claude Code's final result reports, so a session that used several models reports one usage per model. The Codex adapter is unchanged.

### Context

Today the adapter sums every model into one figure, so the detail is lost before crew sees it; #315's part 5 records it by model. This part completes R16 by filling the list part 1 added. "Part 5" in the plan's text below is #315's part 5.

### Key Decisions

- **Unreported usage is not zero.** A measure that will gain its own granularity lives in its own records: a session's tokens are records by model that exist only when the harness reported them, so a stopped session reads as not reported and a shell reads as 0. Governs R13, R14. (session-settled: user-approved — chosen over a nullable token column and over storing 0: zero would make failed sessions look free)
- **The core decides what to record, the engine writes it.** The core already knows the issue, its labels, the run's rule, action, bot, verdict and route, so it builds the records and emits commands; the engine executes them through the port, the way it executes journal records today. Crew's own time reaches the core with the fact the engine hands it, so the core keeps no clock. Harness-specific detail stays in the harness's adapter. Governs R7, R8, R9, R10, R11, R12, R16. (session-settled: user-approved — chosen over the engine assembling records on its own: the core keeps the decision pure and table-testable)

## Planning Contract

### Key Technical Decisions

- KTD1. **`crew.Usage` gains a per-model list, kept beside `Tokens` and `Models`.** A new `ModelTokens` (a model's name and its `Tokens`) and a `Usage.ByModel` list of them, sorted by model name, empty when the harness does not tell tokens by model. `Tokens` stays the session's sum and `Models` its model names: the Codex adapter reports a sum with no model, and the journal, the live view, the status comment and `Spend` read only those two fields, so none of them changes. A sorted list rather than a map keeps the core's events deterministic for table tests and for part 5's records, and follows how `Models` is already a sorted list.
- KTD2. **The Claude Code adapter fills `ByModel` from the same `modelUsage` it already sums, in the same pass.** One entry per model the last result lists, its four counts as given, so `Tokens`, `Models` and `ByModel` cannot disagree. A model listed with four zero counts keeps its entry: it was reported (first Key Decision). An empty `modelUsage`, or no result, leaves `ByModel` empty, as it leaves `Tokens` unreported today.

### Assumptions

- The per-model detail is what the final result's `modelUsage` gives (input, output, cache read, cache write per model name), with no further split by subagent or skill; #315 defers those to its model-call slices.

### Sequencing

## Implementation Units

### U2. The Claude Code adapter reports tokens by model

- **Goal:** a Claude Code session's usage lists the tokens of each model its final result reports.
- **Requirements:** R16; KTD2.
- **Dependencies:** U1.
- **Files:**
  - Modify: `internal/adapter/claude/stream.go` (`stream.usage` builds `ByModel` while it sums `modelUsage`; its doc comment says so).
  - Modify: `internal/adapter/claude/harness.go` (the `Usage` doc comment names the per-model tokens).
  - Test: `internal/adapter/claude/usage_test.go`.
- **Approach:** in the loop that already sums `s.last.Models`, also collect one `ModelTokens` per model, then sort them by model name, set only when the map is not empty, as `Tokens` and `Models` are.
- **Patterns to follow:** the existing `stream.usage` and its `slices.Sorted(maps.Keys(...))` for `Models`; the fixture-driven tests in `internal/adapter/claude/usage_test.go`.
- **Test scenarios:**
  - `success.jsonl`, one model: the usage holds one `claude-opus-5-5` entry with input 14, output 132, cache read 38216 and cache write 5360, beside today's sum, cost, turns and models.
  - `multiresult.jsonl`, the last result listing Opus and Sonnet: the usage holds two entries, `claude-opus-5-5` then `claude-sonnet-5-5`, each with its own four counts, and `Tokens` is still their sum.
  - `error.jsonl`, an empty `modelUsage`: no per-model entries, and still no tokens.
  - A result whose `modelUsage` lists a model with four zero counts: that model has an entry with zero counts, and `Tokens` is reported as zero.
  - No result, a session ended by a signal, and a session crew stopped: the usage is still nothing, with no per-model entries.
- **Verification:** the Claude adapter's usage tests pass with the per-model entries, and the Codex adapter's tests pass unchanged (its usage has no per-model entries).
